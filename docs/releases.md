# Releases and reproducibility

## Scope

This release provides SPLASH for processing new user-supplied data. It includes
the registration pipeline, local setup/point-selection interfaces, configuration
and validation, acquisition-row preparation, and a generated synthetic example.

The software citation describes the code. It does not imply that a particular
published experiment, dataset or accuracy result is reproduced by the example.

## Record a processing run

Retain the following together:

- The software version or Git commit and the environment specification.
- Input file identifiers and raster sidecars, including band wavelengths,
  no-data metadata, coordinate reference system and acquisition-row IDs.
- `resolved_config.json` and `run_metadata.json` from the output directory.
- Selected manual correspondences, homographies and their input metadata.
- Saved processing models and transformation files from the same run.
- Final ENVI binaries and headers, including their valid-footprint masks.

The output manifest identifies the products generated by an execution. Do not
combine cached transformations from different input grids or acquisitions.

## Reusing processing state

Saved homographies are reusable only with matching input geometry and metadata.
Headless mode verifies that association. Generate a new manual registration for
changed inputs, rather than renaming an unrelated matrix to satisfy the expected
filename.

ShapeShifter and elastic outputs depend on the data passed into their stages.
Retain the preceding-stage products and configuration when investigating a
processing difference. Fixed seeds and thread counts help make that investigation
repeatable.

This release retains floating-point values during elastic band resampling,
keeps categorical row IDs separate from spectral interpolation, checks shift
bounds, and exports the full spectral-band set with explicit footprint masks.
These changes affect numerical outputs compared with legacy local scripts.
Use the recorded release and configuration for a new run; this release does
not promise identical results to historical experiments.

## Interpreting outputs

SPLASH performs spatial alignment. It does not establish radiometric calibration,
spectral-fusion quality, or positional accuracy without an independent evaluation.
The generated demo is an execution check on constructed data.

Use independent, suitable correspondences or other reference information when
quantifying alignment of a new acquisition. QA intensity-difference rasters and
warped grids support inspection; they are not calibrated error bounds.

## Release checklist

Before distributing a new software version:

1. Run input-validation checks and the generated example in the documented
   environment.
2. Exercise the setup, point-picker and preview interfaces on a local dataset.
3. Check the final spectral-band counts, output grids and raster sidecars.
4. Confirm that saved transformation metadata rejects mismatched inputs.
5. Update the version, changelog and citation metadata together, and record the
   commit used for the release.
